# Deepmarks 0.9.0

Deepmarks 0.9.0 is a **security + archive-reliability** release. The
archive worker's URL-fetch path is now defended against DNS rebinding,
the SSRF guard the API and worker share no longer diverges on edge
cases, and the archive pipeline picks up seven new media hosts, an LLM
fast-fallback path, and four audit batches of capture fixes. This is a
server/source release — nothing about the user's data model, keys, or
portability changes. If Deepmarks vanished, every bookmark you saved
is still readable from Nostr, exactly as before.

Ships alongside Android / Zapstore build 2.2.11 (`versionCode` 41) and
iOS 2.2.11 / build 40.

## SSRF hardening on the archive worker

The archive worker fetches user-submitted URLs in a privileged network
position: it can reach Redis on Box A, the bunker on Box C, and the
Linode metadata service. The SSRF guard rejects single-label hosts,
localhost, RFC1918, link-local, CGNAT, IPv6 ULA, and `::ffff:` mapped
v4 — that filter predates 0.9.0. Two gaps are now closed:

- **DNS rebinding / TOCTOU.** The guard resolved the hostname, validated
  the addresses, and then Playwright / `fetch` did their *own* DNS
  resolution milliseconds later. An attacker flipping the host's A
  record between those two calls could steer the fetch at a private
  target. New `safeFetch` resolves once, validates, and **pins one
  address into an undici `Agent` with a custom `lookup`** that ignores
  the live resolver. The redirect-walking
  `resolveSafePublicHttpUrl` pins per hop. IP-literal URLs skip pinning
  (nothing to rebind). See
  [`archive-worker/src/safe-url.ts`](../archive-worker/src/safe-url.ts).
- **`looksLikeIp` parity.** The API and archive-worker copies of the
  guard had drifted. The API copy used `node:net.isIP` (strict); the
  archive-worker copy used `/^[0-9.]+$/ || /^[0-9a-fA-F:]+$/`, which
  mis-classed hex single-label hosts like `deadbeef` as IPs and then
  mishandled them downstream. The archive-worker copy now uses
  `node:net.isIP` with the same bracket-stripping the API copy has, so
  both copies of the guard behave the same on every input.

`undici` is now a runtime dependency of `archive-worker`.

## Idempotent registry backfill

On every API boot, `backfillRegistry` re-SCANned three Redis namespaces
(`dm:lifetime:*`, `dm:username:bypubkey`, `dm:public-bookmarks:author:*`)
and SADDed every pubkey into the relay's registered set. SADD is
idempotent at the data level, but a container restart paid the SCAN cost
again and spammed an `added: 0` log line every boot. The backfill now
guards on a `SET NX` marker (`dm:registry:backfill-done:v1`) so
subsequent boots short-circuit; the marker is cleared on partial
failure so the next boot retries. Mirrors the older
`archive-refcount.ts::backfillFromExistingArchives` pattern.

## Wider media archive coverage

Lifetime and media-add-on archives now recognise and capture audio and
video from seven more hosts:

- **SoundCloud** (player and API-redirect enclosures)
- **Bandcamp** (album and track pages)
- **Mixcloud** (cloudcasts)
- **Dailymotion** (videos)
- **Streamable** (clips)
- **BitChute** (videos)
- **Kick** (live and VOD streams)

`media-helpers.ts` was extracted from the worker's main loop as a
tested module so content-type sniffing, filename derivation, and
media-vs-page routing decisions are unit-covered rather than
exercised only by the staged media smoke suite.

## LLM enrichment: Cerebras fast fallback + timeout discipline

DeepInfra is the primary LLM provider for bookmark enrichment,
summaries, tags, semantic embeddings, and rescue suggestions. Two
operational gaps closed:

- **A separate, modest chat-completion timeout.** Previously a single
  long timeout covered the whole enrichment surface. A DeepInfra
  latency spike on a chat completion would hold the job open until the
  job-level timeout dropped it. The new `DEEPINFRA_CHAT_TIMEOUT_MS`
  caps only the chat-completion step so a slow chat doesn't sink the
  job.
- **Cerebras `gpt-oss-120b` as a fast fallback.** When DeepInfra times
  out or errors on a chat completion, the worker falls back to
  Cerebras's `gpt-oss-120b` (a fast inference host) before failing the
  job. Cerebras is wired through its own env (`CEREBRAS_*`) and only
  activates on DeepInfra error; an empty-string env no longer silently
  disables the fallback (`||` instead of `??`).

## Archive worker audit batches 2–4

A continuing robustness pass over the archive pipeline. Each batch is
ship-by-batch; full notes in the commits and
[`reliability-2026-06.md`](../reliability-2026-06.md).

- **Batch 2 — render-budget, bot-challenge, transient retry.** Bot-wall
  and consent-interstitial pages are now *rejected* instead of archived
  (no more saving a cookie-banner page as a snapshot). Transient HTTP
  failures get a bounded retry rather than a single-shot permanent
  failure. The render budget is enforced so a wedged page can't hold a
  worker slot forever.
- **Batch 3 — direct-file integrity + extensionless + redirect + long
  media.** Direct PDF / media / document downloads now have integrity
  checks (no more dropping bytes on truncation), extensionless URLs are
  sniffed by content-type, redirect/transient HTTP failures on file
  fetches retry, and long media captures don't run out of budget
  mid-stream.
- **Batch 4 — social + rescue depth.** Tweet capture now goes through a
  FixTweet-style standalone-HTML path so a tweet is archived as
  content, not as a Twitter JS shell. Nostr note targets are captured
  the same way. `archive.today` is consulted alongside Wayback for
  rescue, and Wayback timestamps are now correct (the previous query
  used the wrong parameter and could return the closest snapshot by
  luck, not by timestamp).

## Operator-facing changes

- The API now shuts down its background workers cleanly on `SIGTERM` /
  `SIGINT` and surfaces a `warn` line when a backfill pass partially
  fails.
- `archive-worker` exposes `safeFetch` and `resolveSafePublicHttpUrl`
  as the recommended internal entry points for any fetch of a
  user-controlled URL. Per-host fetch sites (`podcast.ts`,
  `direct-file.ts`, `mirror-targets.ts`, the worker's own wayback
  fetch) still call `assertSafePublicHttpUrl` for the validate-only
  path; the redirect-walking fetcher in `safe-url.ts` now uses
  `safeFetch` so each hop is pinned.
- `bunker/` and `browser-extension/` are unchanged in this release;
  no redeploy of Box C is required.
