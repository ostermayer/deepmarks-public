# Deepmarks 0.8.0

Deepmarks 0.8.0 is the **modularization** release. The server side was
refactored from one monolithic process into a small fleet of focused
processes, the archive pipeline learned to find publicly-archivable
alternatives when a page blocks capture, and the app gained an
overlay-based "add a bookmark" flow. This is a server/source release —
nothing about the user's data model, keys, or portability changes. If
Deepmarks vanished, every bookmark you saved is still readable from
Nostr, exactly as before.

## How the server is built now (the big refactor)

Before 0.8.0 a single Node process on Box A — historically named
`payment-proxy` — did *everything*: it served the entire HTTP API,
listened for Lightning settlements, and ran ten background workers
(search indexing, relay fanout, onboarding scans, zap counting, LLM
enrichment, the daily Pinboard post, and more) in one event loop. The
name was a relic; the process had quietly become a monolith.

0.8.0 splits that into **one HTTP API plus four task-specific worker
containers**, all built from the same image and selected at startup by a
`WORKER_GROUP` setting:

| Process | Responsibility |
|---|---|
| **api** (was `payment-proxy`) | The HTTP API only — bookmarks, search, LNURL/zaps, `/api/v1`, archives, accounts, admin, favicon cache |
| **worker-search-indexer** | Keeps the Meilisearch index, per-URL save-counts, and zap totals fresh from the relay |
| **worker-relay-sync** | The outbox: relay fanout, onboarding import, follows ingest, profile resolution, the daily Pinboard post |
| **worker-enrichment** | LLM enrichment of bookmarks (summaries, tags, categories, semantic vectors) |
| **worker-payments** | The Lightning invoice listener (zap receipts), lifetime-archive backfill, lifetime-label recovery |

Why it matters:

- **Isolation.** A wedged relay subscription or a slow LLM call can no
  longer stall Lightning settlement or the request path. Each group
  crashes, restarts, and scales independently.
- **Smaller blast radius for secrets.** The Voltage (Lightning) macaroon
  now lives only on the API and the payments worker; the bunker signing
  key only on the processes that actually sign. The indexer and
  enrichment workers hold neither.
- **Honest naming.** Because the service is now *only* the API, the
  `payment-proxy` package/service/image was renamed end-to-end to
  **`api`** (directory, compose service, Caddy upstream, deploy + CI
  scripts). The public URL `api.deepmarks.org` and every client are
  unchanged — clients always talked to the public hostname, never the
  internal container name.

How the processes talk to each other did not change conceptually — they
still coordinate through **Redis queues and the strfry relay**, never
through shared memory — which is exactly what made the split safe. The
workers used to borrow the API's connections in-process; now they open
their own and run as separate containers. A single process can still run
the whole fleet (`RUN_WORKERS=all`) for local development and single-box
deployments.

Full topology: [`system-overview.md`](../system-overview.md) and
[`architecture.md`](../architecture.md).

## Archiving, now augmented by search + LLMs

A Lifetime archive snapshots a public page so it survives link rot. When
that capture fails because the site blocks scrapers (paywalls, bot walls,
JavaScript-only pages), Deepmarks no longer just records the failure — it
tries to find a **publicly-archivable alternative** and archive that
instead:

- **URL variants** — http/https, www, query-stripped, AMP/print views.
- **Wayback + archive.today** snapshots of the same URL.
- **Scholarly open-access PDFs** — for an article with a DOI/PII, it
  queries OpenAlex/Crossref and constructs publisher PDF variants, then
  archives the open-access copy. A paywalled Lancet link becomes its
  open full-text PDF.
- **Social-media mirrors** — an `x.com` tweet that renders as an empty
  JavaScript shell is rescued through a Nitter-style mirror
  (`xcancel.com`, `nitter.net`) that serves the same tweet as static,
  archivable HTML.
- **LLM + searxng discovery** — a self-hosted [searxng](https://searxng.org)
  metasearch plus an open-source LLM suggest public mirrors and search
  queries. The same LLM generates the bookmark summaries, tags, and
  semantic vectors that power search.

Every candidate is held to a strict safety bar: it is SSRF-checked (DNS
resolved, private/internal ranges rejected, re-checked after redirects),
size- and content-type-bounded, and **only accepted when it is a known
archive host, a host-related page, or an identifier-matched scholarly PDF
or allowlisted mirror of the same item.** A rescue can never archive
arbitrary unrelated content under your bookmark.

Detail: [`archives.md`](../archives.md) and
[`llm-augmentation.md`](../llm-augmentation.md).

## App: add-a-bookmark overlay

"+ add a bookmark" now opens a centered modal overlay that matches the
search overlay (backdrop blur, Esc / click-outside to close, focus moves
into the form and restores on close), instead of an inline panel — so
saving a URL feels the same as searching for one.

## Operator-facing

- **Quieter alerts.** Best-effort media-archive failures (e.g. a tweet
  with no video) are recorded for the user but no longer email the
  operator or flood the enrichment queue.
- **`archive-rescue` admin command** re-runs the rescue pass over
  recorded failures (`deploy/admin.mjs archive-rescue --run`).
- **Deploy note.** On the multi-service Box A, deploy *targeted* services
  rather than a full rebuild — a bare full build recompiles strfry from
  C++ source and is memory-heavy.

Ships alongside Android / Zapstore build 2.2.7 (`versionCode` 37).
