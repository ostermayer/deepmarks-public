# Deepmarks 2.0.2

Deepmarks 2.0.2 focuses on making friends bookmarks feel immediate and
polished across web, iOS, and Android:

- Hides unresolved NIP-51 note targets from the friends feed instead of
  showing placeholder rows or raw event ids.
- Renders `nostr:` profile and post references as readable profile/post
  links across bookmark cards, landing feed rows, saved-post views, and
  zap dialogs.
- Removes boxed styling from link metadata previews so friends-bookmark
  rows match the cleaner bookmark-list presentation.
- Retries unresolved note targets during feed priming so posts can appear
  after the server cache catches up.
- Proactively warms friend identity metadata and historical bookmark/list
  content through the server-side follows ingester.
- Treats active bookmark publishing as a cache-warm signal: known follows
  are prioritized immediately, and missing contact caches trigger a
  bounded onboarding refresh before the user opens the friends feed.
- Caches watched friends' latest profile events as soon as they are seen,
  reducing npub fallbacks in friend pickers and feed bylines.
- Updates the public source documentation to use formal architecture,
  deployment, and technical references without informal checklist styling.
- Avoids native-app boot hangs from stale WebView service-worker caches
  by registering the service worker only on web and adding a native boot
  recovery pass.

The release keeps the app version aligned across the web app, Android,
iOS, Zapstore metadata, and the public source release tag.
